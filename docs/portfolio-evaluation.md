# 초기 입력과 포트폴리오 평가

버전 1.0 · 확인일 2026-11-14

## 입력과 실행

상시 HTML `http://127.0.0.1:8788`에서 목표·기간, 자산·현금, 소득·지출, 납입·리밸런싱, 선호/제외 섹터, 위험 선호와 수치 제한을 입력해요. 위험 선호는 숫자를 자동 결정하는 점수표가 아니에요. 선호는 모델의 분석 기준, 제외·상한·하한은 코드 검증 조건이에요. 별도 메모 제약은 검증 에이전트가 판단해요.

토스 조회는 미국 보유·기본 정보·가격·환율·섹터만 읽어요. 매수가능금액을 현금으로 복사하지 않아요. 원화/달러 현금은 사용자가 확인해요. 현재 보유가 없어도 앞으로 운용할 자금으로 제안할 수 있지만 실제 보유액은 0으로 남겨요. 기존 보유 포함 총액과 추가 투자금을 구별하고 합의한 운용 한도를 검사해요.

후보 티커는 선택 입력이고 현재 보유는 자동 포함해요. 비워두면 토스의 시총순 목록에서 선호 섹터별 상위 3개와 대분류별 상위 2개를 모아 제외 섹터를 제거한 최대 30개 주식을 후보로 사용해요. 후보 선택법과 대형주 편향을 입력 화면·실행 맥락에 남겨요. 전체 시장 탐색이 아니며 ETF는 직접 지정해요. 모델은 제공한 자료만 사용해요. 토스 시세·기본 정보는 기업 가치·거시/뉴스 리서치를 대체하지 않으며 충분한 근거가 없으면 보류해야 해요. 실제 보유와 제안은 다른 이벤트로 저장하고 같은 날 수정 제안은 `revision_of`와 이유를 남겨요. 실제 주문 경로는 없어요.

`portfolio.sqlite3` / `portfolio-session.json`은 `.local/service/`에, 모델 키는 `.local/model.json`에 저장해요. 비밀 파일과 DB는 0600이고 Git에서 제외해요. 데모는 `demo.sqlite3`로 분리해요. 생성은 백그라운드에서 진행하며 재시작 중단은 기록하고 자동 재호출하지 않아요. 이 화면은 초기 생성과 명시적 재평가용이며 실제 사용자 주간 자동 평가 스케줄러는 아직 연결하지 않았어요. 별도 데모만 주간 자동 평가해요.

## 평가 계층

독립 관점마다 `mara.risk.evaluate`가 계산하고 R4 검증 에이전트가 정성 검토해요. R5 리더 종합 뒤 같은 계산과 R4 검토를 다시 실행해요. `errors` 또는 `missing`이 있거나 최종 정성 검증에 실패하면 제안을 보류해요. 경고와 계산 불가 항목도 화면에 보여요.

| 항목 | 계산 또는 기준 | 한계 |
|---|---|---|
| 비중·시장 | 합계 1, 롱온리, 허용 시장·상장 상태·종목 상한 | 적합한 가치 평가를 보장하지 않아요 |
| 섹터 노출 | 상품 비중 × 출처의 섹터 노출 | 토스 자체 분류가 겹치면 각 섹터에 전액 노출로 기록하며 합계가 100%를 넘을 수 있어요 |
| ETF 내부 노출 | 제공자 내부 구성 자료가 있을 때만 계산 | ETF 개수나 이름으로 내부 분산을 추측하지 않아요. 자료 부족 상태에서 섹터 제한 통과 불가 |
| 집중도 | 현금 제외 종목 비중을 정규화한 HHI = Σw², 유효 종목 수 = 1/HHI | 상품 단위 지표이며 ETF 내부 중복과 상관관계를 반영하지 않아요 |
| 자산군·통화 | 확인된 자산 분류와 표시 통화별 비중 | ETF 기초 자산 미확인은 unknown. 표시 통화는 환헤지 반영 순위험이 아니에요 |
| 현금·납입 | 필요 현금/최소 비중, 현금÷월 지출, 월 환산 납입과 소득−지출 비교 | 별도 자금·은퇴 인출 계획은 정성 검토해요 |
| 스트레스 | Σ(비중 × 자산별 하락 가정), 운용액 × 손실률 | 토스 연결 기본 가정은 모든 위험자산 가격 −50%. 예측·최대 손실 보장이 아니며 환율/유동성 위험을 완전히 반영하지 않아요 |
| 회전율 | 실제액과 제안액이 같을 때 ½Σ\|제안 비중−현재 비중\| | 자금 추가/제외가 있으면 계산하지 않아요 |
| 비용 | 확인된 연 보수율의 비중 가중합과 미확인 비중 별도 표시 | 거래비용·세금 총액이 아니에요 |

## 과거 수익률 지표

`risk_history`가 있으면 현재 비중을 매일 리밸런싱한 가상 과거 수익률을 계산해요. 연환산 변동성, 일별 초과수익률의 평균/표준편차 × √252인 Sharpe ratio, 누적 수익 경로의 최대 낙폭, 선택한 벤치마크 beta, 자산 쌍의 상관관계를 제공해요. 분모가 0이면 비율은 null이에요. 실제 운용 성과나 미래 예측이 아니에요.

동일 기간·통화, 출처·인지일, 배당/분할 반영 수익률, 현금·무위험 수익률, 결측 없는 최소 60개 일별 관측을 요구해요. 60개는 구현의 최소 자료 기준이며 통계적 충분성을 보장하지 않아요. 토스 온보딩은 이 과거 수익률 팩을 수집하지 않으므로 현재 화면에서는 계산 불가로 표시돼요. 숫자 0이나 수익률 가정을 대신 넣지 않아요. 별도 실제 시장 팩 공급자는 다음 계약을 사용할 수 있어요.

```text
risk_history:
  dates: 오름차순 YYYY-MM-DD 배열 (60~2520개, 중복 불가)
  base_currency: 시장 팩과 동일
  frequency: daily
  return_type: total_return
  source: HTTPS 원문 URL
  known_at: 인지일 (마지막 관측 이후, 평가일 이하)
  returns: {티커: 일별 수익률 배열, CASH: 일별 현금 수익률 배열}
  risk_free_returns: 같은 일자·통화의 무위험 수익률 배열
  benchmark_returns: 선택 사항, 같은 일자·통화의 벤치마크 수익률 배열
```

## 근거와 구현 선택

- [Investor.gov — 자산 배분과 분산](https://www.investor.gov/introduction-investing/getting-started/asset-allocation): 목표 기간·위험 감수 능력과 자산 배분을 연결해요. 이를 개인 맥락과 별도 제한 입력으로 해석했어요.
- [CFA Institute — Sharpe ratio와 information ratio](https://rpc.cfainstitute.org/-/media/documents/code/gips/sharpe-ratio-and-the-information-ratio.pdf): Sharpe ratio의 위험 조정 성과 측정과 해석 한계를 확인했어요. 단일 점수나 자동 통과선으로 사용하지 않아요.
- [토스 OpenAPI 원본](https://openapi.tossinvest.com/openapi-docs/latest/openapi.json): 보유의 marketCountry/currency, 시세 timestamp, 환율 midRate, 자체 중복 섹터 분류를 확인했어요. 섹터 관련 ETF 목록을 ETF 내부 보유 비중으로 간주하지 않아요.

지표 선택·최소 관측 수·차단 조건은 구현 정책이며 위 자료가 정한 일률적인 투자 기준은 아니에요. 계산 규칙 버전과 사용한 시장·사용자 입력, 가이드 원문은 실행별로 보존돼요.
