# 투자 판단 리포트

버전 1.2 · 2026-11-18

보고서는 당시 완료 기록과 시장 자료, 개인 맥락, 역할별 출력을 연결해요. 최종 검증이 끝난 뒤 `final_report`를 구성해 완료 이벤트와 함께 저장해요. 새 분석으로 과거 판단을 다시 쓰지 않아요. 예전 형식의 보고서는 원본을 보존한 채 현재 화면에서 표시 문서를 만들고, 그 상태를 구분해요.

## 읽는 순서

1. **현재 시장 상황**: 보고서 기준 시점의 시장 해석을 발췌해 보여 줘요. 당시 fact의 ID·발표일·원문은 버튼에서 확인해요. 전체 시장 해석은 펼쳐 읽어요.
2. **포트폴리오 요약**: 현재 평가액, 기간 손익과 Modified Dietz 수익률, 입출금을 포함한 평가액 변동률을 구분해요. 보유별 평가액·비중과 가격 변동률을 같은 표에서 읽어요. 최초 평가나 입출금 미대조 상태의 손익·수익률은 계산 불가로 표시해요.
3. **포트폴리오 조정안**: 현재 금액 → 조정 후 금액 → 증감액을 비교해요. 목표에서 빠진 실제 보유도 표시해요. `future_income` 계획은 기존 보유를 유지하고 신규 납입액을 더한 가정으로 표시하며 납입분 비중과 전체 보유 비중을 혼동하지 않아요. 추가 자금과 제안 범위 밖 금액, 보류 상태, 납입 주기와 적용 조건도 확인해요.
4. **주요 근거**: 종합안에 저장된 핵심 요약과 제안 이유를 먼저 읽어요. 판단별 설명·가정·반론·fact·계산 근거와 최종 검토는 펼쳐 확인해요. 저장된 문장을 새 판단으로 바꾸거나 임의로 중요도 점수를 매기지 않아요.

대안과 미해결 질문, 재검토 일정, 상세 계산·역할별 원문·수정 이력은 별도 접기에 보존해요. 옆 목차는 네 구역과 분석 원본으로 바로 연결해요. 보고서 아래의 분석 과정에서는 에이전트별 입력·출력과 대화를 확인해요. 미완료 실행을 고르면 이전 완료 보고서를 숨겨 두 상태가 섞이지 않게 해요.

완료 보고서는 처음부터 펼쳐서 보여요. 저장본을 선택하면 보고서 제목으로 이동하고, 자동 갱신은 읽던 위치를 바꾸지 않아요. 개인 맥락을 수정하려면 상단의 ‘나의 페르소나’를 선택해요.

보고서의 구성 입력과 본문 해시, schema와 원본 재조립 결과를 대조해요. 자기 해시가 맞는 것만으로 저장 문서를 신뢰하지 않아요. 근거의 저장 구조와 시계열 확장은 [fact와 판단 연결](facts.md)에 정리했어요.

## 시각화와 해석

- 자산별 세 막대는 각 구성의 총액 대비 비중이에요. 제안 자금과 실제 보유액이 다르면 같은 비중의 금액도 다르므로 금액을 별도 표시해요. 이전 제안이나 실제 보유가 없으면 비교 없음으로 표시해요.
- 시세 변화는 두 시장 팩의 관측 가격을 비교해요. 배당·분할·입출금 조정 투자 수익률이 아니고 원화 환산 가격은 환율 영향도 포함해요. 비교 시점과 통화가 맞지 않으면 변화를 계산하지 않아요.
- 섹터 상한은 세로선, 상한 초과는 별도 색, 미확인 노출은 빗금으로 구분해요. 수치와 문구도 같이 표시해 색만으로 해석하지 않도록 해요. 분류가 중복되면 합계가 100%를 넘을 수 있어요.
- 검증된 과거 수익률이 없으면 변동성·Sharpe ratio·최대 낙폭을 계산 불가로 표시해요. 추정 수익 곡선이나 점수는 만들지 않아요. 입출금 대조가 끝나지 않은 실제 성과도 계산 불가로 남겨요.
- 최초 평가는 아직 결과 회고가 없어요. 예전 형식의 에이전트 출력에 새 요약 필드가 없으면 이를 표시하고 남아 있는 원문과 기존 내용을 읽어요. 과거 분석을 새 모델로 채워 넣지 않아요.
- 데모는 실제 데이터와 별도 DB를 사용하고 리포트 상단에 합성 자료임을 표시해요.

라이트·다크 모드, 좁은 화면의 세로 카드, 옆 목차, 표 가로 스크롤, 인쇄용 스타일을 제공해요. 인쇄 시 핵심 판단과 출처를 포함하고 긴 역할 원문과 대화 작업실은 제외해요. 인쇄 후 기존 접힘 상태로 돌아와요. PDF 저장은 사용자의 브라우저 인쇄 창에서 수행해요. 개인 리포트는 로컬 화면에만 제공하며 외부에 게시하지 않아요.

## 실행 범위와 검증

실제 보고서는 HTML 생성/재평가로 만들어요. 이전 완료 평가가 있으면 판단과 회고를 다음 실행에 전달해요. 주간 자동 실행은 현재 별도 데모에만 연결되어 있으며 실제 사용자 자동 갱신에는 시장 자료 갱신·보유와 입출금 확인 흐름을 더 연결해야 해요.

`python3 -m unittest discover -s tests -q`로 시점 연결·소유권·원본 보존과 기존 분석 흐름을 검증해요. `node --test tests/*.mjs`는 실제 HTML/JS를 Happy DOM에서 실행하며 초기/주간 보고서, 비중 비교, 결측·미대조 수익률, 과거 출력 호환, 안전한 텍스트 표시, 화면 이동·인쇄 상태 복원을 검사해요. 설치 방법은 `tests/dashboard-feedback.mjs` 상단에 있어요. 서비스에는 JS 테스트 의존성을 추가하지 않아요.
