# 투자 판단 리포트

버전 1.0 · 2026-11-14

리포트는 해당 시점의 완료 기록, 시장 팩, 개인 맥락과 에이전트 출력을 연결해 읽는 화면이에요. 새 분석으로 과거 이유를 다시 쓰지 않아요. `mara.reporting.present`가 읽기 전용 `view`를 조립하며 원본 이벤트는 그대로 남아요. 사용자의 세션으로 읽을 수 있는 기록만 연결해요.

## 읽는 순서

1. **판단 요약**: 최초/주간/같은 날 수정본 구분, 평가 구간, 유지·조정·보류와 이유, 실제 평가액·제안 기준액·추가 필요 자금.
2. **시황 분석**: 시장 근거 에이전트의 상황 요약, 확인된 요인, 이전 평가 이후 변화, 개인 포트폴리오에 대한 해석, 불확실성과 자료 공백. 인용 번호로 당시 근거에 이동해요.
3. **독립 투자 관점**: Buffett·Marks·Bogle 각각의 판단 근거, 제안 비중, 지난 판단 대비 변화, 가정·위험·반대 근거, 판단을 바꿀 조건, 다음 확인. 관점별 비중과 최종 제안 비중을 같은 표에서 비교해요. 인물의 실제 최신 추천이 아니라 출처를 바탕으로 작성한 철학 가이드의 실행 결과예요.
4. **리더 종합**: 실제 보유·이번 제안·지난 제안을 비교하고 전제 변화, 검증 지적에 대한 응답, 남은 의견 차이·위험, 다음 평가 항목을 읽어요.
5. **포트폴리오 평가**: 집중도·현금 여력·가정한 손실과 과거 위험 지표, 섹터 상한·미확인 노출, 자산군·표시 통화, 수치·정성 검증의 지적과 한계.
6. **결과와 회고**: 투자 결과와 분석·검증 과정 평가를 구분해요. 지식 관리 에이전트의 갱신 제안·이유, 보존한 불확실성, 정기 점검 기록과 다음 일정을 함께 보여요.
7. **근거**: 당시 사용 가능한 원문 자료의 발표·인지·유효 시점, 내용과 자료 한계. 모든 역할 호출의 입력·출력 ID, 가이드 hash, 실행 제공자를 접어둔 상세에서 확인해요. 두 번 실행한 검증 기록도 모두 연결해요.

## 시각화와 해석

- 자산별 세 막대는 각 구성의 총액 대비 비중이에요. 제안 자금과 실제 보유액이 다르면 같은 비중의 금액도 다르므로 금액을 별도 표시해요. 이전 제안이나 실제 보유가 없으면 비교 없음으로 표시해요.
- 시세 변화는 두 시장 팩의 관측 가격을 비교해요. 배당·분할·입출금 조정 투자 수익률이 아니고 원화 환산 가격은 환율 영향도 포함해요. 비교 시점과 통화가 맞지 않으면 변화를 계산하지 않아요.
- 섹터 상한은 세로선, 상한 초과는 별도 색, 미확인 노출은 빗금으로 구분해요. 수치와 문구도 같이 표시해 색만으로 해석하지 않도록 해요. 분류가 중복되면 합계가 100%를 넘을 수 있어요.
- 검증된 과거 수익률이 없으면 변동성·Sharpe ratio·최대 낙폭을 계산 불가로 표시해요. 추정 수익 곡선이나 점수는 만들지 않아요. 입출금 대조가 끝나지 않은 실제 성과도 계산 불가로 남겨요.
- 최초 평가는 아직 결과 회고가 없어요. 예전 형식의 에이전트 출력에 새 요약 필드가 없으면 이를 표시하고 남아 있는 원문과 기존 내용을 읽어요. 과거 분석을 새 모델로 채워 넣지 않아요.
- 데모는 실제 데이터와 별도 DB를 사용하고 리포트 상단에 합성 자료임을 표시해요.

라이트·다크 모드, 좁은 화면의 세로 카드, 옆 목차, 표 가로 스크롤, 인쇄용 스타일을 제공해요. 인쇄 전 상세 내용을 펼치고 인쇄 후 기존 접힘 상태로 돌아와요. PDF 저장은 사용자의 브라우저 인쇄 창에서 수행해요. 개인 리포트는 로컬 화면에만 제공하며 외부에 게시하지 않아요.

## 실행 범위와 검증

실제 보고서는 HTML 생성/재평가로 만들어요. 이전 완료 평가가 있으면 판단과 회고를 다음 실행에 전달해요. 주간 자동 실행은 현재 별도 데모에만 연결되어 있으며 실제 사용자 자동 갱신에는 시장 자료 갱신·보유와 입출금 확인 흐름을 더 연결해야 해요.

`python3 -m unittest discover -s tests -q`로 시점 연결·소유권·원본 보존과 기존 분석 흐름을 검증해요. `node tests/dashboard-feedback.mjs`와 `node tests/report-rendering.mjs`는 실제 HTML/JS를 Happy DOM에서 실행하며 초기/주간 보고서, 비중 비교, 결측·미대조 수익률, 과거 출력 호환, 안전한 텍스트 표시, 화면 이동·인쇄 상태 복원을 검사해요. 설치 방법은 첫 번째 테스트 상단에 있어요. 서비스에는 JS 테스트 의존성을 추가하지 않아요.
