# Mara의 구조와 철학

기준일: 2026-11-17 · 현재 구현과 확인된 제품 방향을 설명해요. 개인 계정 정보와 작업별 수정 이력은 포함하지 않아요.

## 1. 무엇을 위한 시스템인가

Mara는 개인의 생활과 목표를 이해하고, 시장 근거와 여러 투자 철학을 연결해 판단 가능한 포트폴리오 제안을 만드는 도구예요. 좋은 종목을 나열하는 데서 끝나지 않고 **왜 선택했는지, 왜 이 비중인지, 무엇이 틀리면 바꿀지, 이후 무엇을 배웠는지**를 이어서 설명하는 것이 목적이에요.

사용자는 자기 상황과 선호를 대화로 알려주고, Mara는 이를 버전 있는 개인 맥락으로 정리해요. 투자 에이전트들은 그 맥락 안에서 서로 다른 대안을 만들고 검증해요. 제안을 받은 사용자는 이유와 반론을 읽고 각 역할에 질문할 수 있어요. 분석·제안과 실제 자산의 변경은 별개의 책임이에요.

## 2. 설계의 중심 원칙

| 원칙 | 구조에 미치는 영향 |
|---|---|
| 개인의 목표에서 출발 | 먼저 상황을 이해하고 투자할 자금의 범위·기간·제약을 정리해요. 기관의 배분이나 유명인의 종목을 그대로 이식하지 않아요. |
| 선호와 사실을 구분 | 공격적인 투자 의지는 확인된 손실 감내능력과 달라요. 관심 종목, 예시 비중, 확정 제약도 따로 다뤄요. |
| 다양한 관점을 보존 | 같은 실행의 다른 투자자 답안을 보지 않고 분석해요. 합의나 평균 비중을 정답으로 간주하지 않아요. |
| 판단과 계산의 책임 분리 | 모델은 해석·가설·반론·종합을, 코드는 수치 계산·계약 검증·권한·저장을 맡아요. |
| 결론은 근거까지 연결 | 출처가 있다는 사실에 더해 그 자료가 해당 주장을 실제로 지지하는지 확인해요. |
| 현재를 개선해도 과거는 보존 | 새 대화와 재분석은 새 버전이에요. 당시 입력과 원본 의견을 나중의 지식으로 덮어쓰지 않아요. |
| 실패와 보류도 설명 가능한 결과 | 부족한 이유와 해소 조건을 남겨요. 보류의 타당성과 분석의 완성도는 따로 평가해요. |

## 3. 전체 의사결정 흐름

**상황 대화 → 개인 페르소나 → 실행 기준 고정 → 개인 맥락·시장 근거 → 독립 투자 관점 → 관점 검증 → 리더 종합 → 최종 재검증 → 보고서·독립 품질 평가**로 이어져요.

다음 평가에서는 **실제 결과 확인 → 투자 결과와 분석 과정 회고 → 활성 지식 갱신·pruning → 바뀐 전제와 시장을 반영한 다음 제안**으로 연결돼요. 최초 실행에는 없는 과거 성과나 회고를 만들어 넣지 않아요.

화면은 이 흐름의 투영이에요. 박스는 역할 또는 그 역할이 수행하는 단계를 뜻하며, 클릭하면 당시 입력·출력·근거·대화를 볼 수 있어요. R4가 두 번 등장하는 이유는 관점별 대안과 최종 선택안을 각각 검증하기 때문이에요. 박스 수가 서로 다른 모델의 수를 뜻하지는 않아요.

## 4. 개인 페르소나는 대화와 계산을 연결한다

Mara에는 서로 다른 두 종류의 페르소나가 있어요. **개인 페르소나**는 사용자의 상황을 이해하는 기록이고, **투자자 페르소나**는 분석 에이전트가 적용하는 철학과 판단 규칙이에요.

개인 페르소나는 관심사·섹터·투자 성향과 함께 소득·지출·자산·부채·현금 필요·납입 계획·기간·제약을 담아요. 각 항목은 원문 출처, 단위, 적용 범위, 기존 기록인지 직접 진술인지 또는 해석·미확인인지 구분해요. 계산의 기준은 구조화된 `profile`이며, 페르소나는 이 값에 연결된 설명과 출처를 제공해요. 자유로운 요약 문장만으로 계산하지 않아요.

일반 대화에서 제안된 변경은 발언·금액·통화·주기·의미와 대조한 뒤 채택해요. 가정이나 질문을 확정 값으로 바꾸지 않으며, 철회한 값은 논쟁 중인 상태로 표시해 그대로 계산에 쓰지 않아요. 기존에 알려진 내용은 다시 묻지 않고, 필요한 경우 선택형 질문을 보여줘요. 이 검사는 자연어를 완벽하게 이해한다는 보장은 아니며 애매한 수정은 보류할 수 있어요.

분석을 시작할 때 profile·실제 보유·persona 버전을 고정해요. 모든 투자 역할과 Q1은 같은 개인 페르소나를 받아요. 분석 중 새 대화로 현재 설정이 달라져도 진행 중인 입력은 바뀌지 않으며 새 설정은 다음 분석에 적용돼요. 과거 보고서는 당시 버전을 표시해요.

긴 입력 폼은 상세 설정으로 남아 있어요. 임시 저장은 초안이며 현재 페르소나의 확정 변경과 달라요. 첫 계좌·시장 연결 등 운영 준비가 없는 신규 사용자는 그 준비를 마쳐야 분석할 수 있어요.

## 5. 역할과 책임

| 역할 | 핵심 질문 | 책임과 결과 |
|---|---|---|
| R1 개인 맥락 | 이 사람은 무엇을 위해 어떤 위험을 감당하며 투자하는가? | 대화로 개인 맥락을 정리하고, 분석 시 목표·현금흐름·제약·미확인 조건을 검토해요. |
| R2 시장 근거 | 지금 무엇을 알고, 개인의 선택에 어떤 의미가 있는가? | 거시·산업·기업·상품 자료를 연결하고 사실·기관 견해·해석·공백을 구분해요. |
| R3 투자 관점 팀 | 같은 조건에서 어떤 선택이 더 나은가? | 각 철학으로 독립 제안, 이유, 가정, 위험, 반증 조건을 작성해요. |
| R4 검증 | 그 주장과 비중이 근거·계산·제약에 부합하는가? | 관점별 검증과 리더 최종안 재검증을 수행해요. 정량 검사와 정성 검토를 결합해요. |
| R5 리더 | 의견 차이와 검증을 고려하면 무엇을 제안할 것인가? | 유지·조정·보류를 종합하고 반대 의견과 판단 변경 조건을 남겨요. 수치 위반을 말로 해제할 수 없어요. |
| R6 회고 | 결과와 과정에서 각각 무엇을 배울 수 있는가? | 당시 기대와 실제 결과, 분석·검증의 누락을 나눠 평가해요. |
| F1 기억 관리 | 다음 판단에 무엇을 남기고 무엇을 정리할 것인가? | 교훈과 기존 지식을 대조해 추가·통합·수정·비활성화·보관을 제안해요. |
| F2 조율 코드 | 어떤 입력과 순서로 실행하고 무엇을 저장할 것인가? | 실행 기준·역할 순서·잠금·계약·이력 연결을 관리해요. 별도 자유 판단 에이전트가 아니에요. |
| Q1 보고서 평가 | 제안의 논증과 보고서가 충분하고 검증 가능한가? | 작성 호출과 분리해 고정 기준으로 평가해요. 총점은 코드로 계산하며 투자 승인 권한은 없어요. |

현재 투자 관점은 Buffett의 사업의 질·가치·안전마진, Marks의 사이클·가격에 반영된 기대·손실, Bogle의 분산·비용·유지 가능성, Wood의 혁신 채택·성장 가치·가정 실패를 사용해요. 실존 인물의 현재 견해를 대변하지 않으며, 말투보다 분석 방법의 차이를 위한 가이드예요.

독립성은 **다른 투자 관점의 현재 답안을 읽지 않는 별도 호출**이라는 뜻이에요. 같은 모델과 공통 자료를 쓸 수 있고, 순차 조사에서 얻은 사실은 뒤 단계에 전달될 수 있어요. 서로 다른 정보원이나 통계적으로 독립적인 오류까지 보장하지는 않아요.

## 6. 자료와 도구: 수집량보다 판단에 쓰인 근거

에이전트는 허용된 도구로 기업 목록 검색·묶음 수집·페이지 비교·기업 재무·공시 본문 검색·가정에 따른 주당 가치 계산을 요청할 수 있어요. 시장 수집 계층은 시세·환율·공식 지표·상품 정보·기관 보고서 등을 근거 형식으로 정리해요. 연구는 허용 목록과 실행 예산 안에서 진행하며 임의 코드 실행이나 주문으로 확장되지 않아요.

자료는 **원문 보관 → 추출·정규화 → 역할 입력으로 전달 → 주장에 사용 → 검증**의 경로를 가져요. 다운로드했다는 사실, 실제 읽었다는 사실, 주장에 충분하다는 판단은 각각 달라요. 활성 예산 때문에 보관만 된 자료도 없는 자료와 구별해요.

금액·통화·재무 기간·관측일·인지일·유효 시점이 맞아야 비교에 써요. 같은 원문의 미러나 반복 인용은 독립 근거를 늘리지 않아요. 자료가 없으면 허용된 대체 원문을 찾거나 주장 범위를 줄여야 하며, 어떤 공백이 결정을 바꿀 수 있는지 드러내야 해요. 모든 공백을 반드시 해소하는 능력이 이미 보장된 것은 아니에요.

## 7. 포트폴리오와 계산의 경계

| 구분 | 의미 |
|---|---|
| 가계 전체 맥락 | 부동산·부채·전체 현금·소득과 지출. 투자 계좌와 중복 여부를 추정해 합산하지 않아요. |
| 실제 포트폴리오 | 확인된 계좌의 수량·현금·기준일·구성 이유. 제안이 나와도 자동 변경되지 않아요. |
| 제안 포트폴리오 | 이번 판단 대상 금액의 계획 배분. 향후 납입은 현재 입금이나 수익이 아니에요. |
| 투자 부분과 현금 완충 | 투자 부분 내부 비중과 전체 자금 기준 비중을 구분해요. 달러 현금도 원화 기준 환율 위험이 있어요. |
| 역사 비교와 스트레스 | 가정에 따른 비교 계산이에요. 실제 계좌 성과나 미래 수익·최대 손실의 보장이 아니에요. |

코드는 자산 평가, 외부 입출금을 구분한 성과, 종목·섹터·ETF 내부 중복, 가계·주가·환율 충격, 비용, 검증 가능한 역사 비교를 계산해요. 필요한 시계열이 없으면 다른 지수의 결과로 해당 조합의 성과를 대신 증명하지 않아요. 리더가 비중을 정하면 선택한 비중으로 다시 계산하고 최종 검증해요.

주간 평가는 판단을 점검하는 주기이고, 리밸런싱은 실제 구성 변경의 주기예요. 유지도 정상적인 제안이에요. 기본 평가는 7일 간격을 판정하며 상시 웹 서버가 있다는 사실만으로 새 시장 자료 수집과 주간 분석 스케줄이 모두 자동 운영된다는 뜻은 아니에요.

## 8. 기억은 원본 기록과 활성 지식으로 나눈다

SQLite의 불변 이벤트가 개인 맥락, 실행 입력·출력, 시장 스냅샷 참조, 제안, 평가, 대화와 회고를 이어줘요. 각 이벤트에는 소유자·적용일·기록 시각·실행 ID·내용 해시가 있어요. 사용자별 접근 범위를 제한하고 공통 시장 자료와 개인 맥락을 분리해요. 로컬 DB 관리자는 신뢰 경계 안에 있으며 공개 다중 사용자 서비스 인증을 대신하는 구조는 아니에요.

fact 원문은 당시 버전으로 보존하고 `report_claims`와 `claim_facts`로 보고서의 판단에 연결해요. 같은 논리 ID의 값이나 출처가 바뀌면 새 snapshot을 만들어요. 읽을 때 원본 이벤트와 색인을 대조하며, 불일치는 숨기지 않아요. [fact 저장과 schema](facts.md)에 표·조회용 view·시계열 확장 범위를 정리했어요.

| 기억의 종류 | 보존·갱신 원칙 |
|---|---|
| 투자 철학·역할 가이드 | 버전 있는 문서와 실행 당시 사본. 단기 수익으로 자동 변경하지 않아요. |
| 개인 맥락·실제 보유 | 새 사실을 새 버전으로 반영해요. 지식 가지치기로 필수 사실을 삭제하지 않아요. |
| 공통 시장 근거·지식 | 출처·시점·적용 조건을 관리해요. 개인 정보가 자동으로 공통 지식에 승격되지 않아요. |
| 실행 원본·대화·회고 | 과거 판단을 설명하기 위한 기록으로 보존해요. 원본을 요약문으로 대체하지 않아요. |
| 활성 지식 | 역할에 필요한 교훈만 예산 안에서 전달해요. 변경 이유와 원본 참조를 남기고 이전 버전으로 복원할 수 있어요. |

Pruning은 현재 판단에 쓸 지식을 정제하는 과정이에요. 반복된 내용은 통합하되 반복 횟수를 신뢰도로 올리지 않아요. 만료·반증된 가정은 제외하고, 모순은 시점·조건·관점으로 구분해요. 장기 원칙과 드문 큰 위험은 최근 사용하지 않았다는 이유만으로 제거하지 않아요. 주간 회고 뒤 개별 갱신과 전체 활성 집합 점검을 함께 수행해요.

현재 목표·제약, 포트폴리오 구성 이유, 미해결 위험과 다음 확인 사항은 별도 핵심 맥락으로 유지해요. 전체 역사를 매번 입력하지 않고 최근 실행의 역할별 투영과 제한된 기억을 사용해요.

‘새 판단 이력’은 원본 삭제 대신 **이전 분석을 현재 판단에서 제외하는 경계**예요. 현재 사실과 실제 보유는 보존하고, 경계 이후의 판단·회고·학습을 새로 이어가요.

## 9. 대화는 두 경로로 판단에 영향을 준다

**내 상황이 바뀌었다면 개인 페르소나 대화**를 사용해요. 현재 맥락을 새 버전으로 바꾸고 다음 분석에 전달해요.

**특정 보고서의 판단에 이견이 있다면 그 역할과 대화**해요. 질문만으로 제안이 바뀌지는 않아요. 판단 변경을 선택해 반영하면 당시 개인·보유·시장 기준을 고정한 새 실행에서 재평가하고 R4·리더·Q1로 이어져요. 현재 구현은 최소한의 뒤 단계만 계산하는 방식이 아니라 전체 판단 단계를 다시 실행하는 방식이에요. 역할은 변경을 수용·일부 수용·거부한 이유를 설명해야 해요.

두 경로 모두 원본 보고서와 실제 보유를 덮어쓰지 않아요. 당시 판단을 재검토하는 일과 오늘의 정보로 새 판단을 만드는 일을 구분해요.

## 10. 무엇을 어떻게 평가하는가

평가는 하나의 점수로 합치지 않아요. **소프트웨어 품질, 투자 과정의 유효성, 제안의 적합성, 보고서 품질, 실제 성과**는 다른 대상이에요. 테스트 통과, R4 통과, Q1 고득점 중 어느 것도 나머지를 대신하지 못해요.

현재 R4·Q1·R6와 개발 리뷰는 구현돼 있어요. 이번에 정리한 별도 애널리스트 프로세스 평가와 외부 보고서의 공정한 대조 실험은 [투자 의사결정 평가 체계](evaluation-framework.md)에 정의했어요. 그 문서는 기존 자동 검사와 새 평가 설계를 명시적으로 구분해요. 비교 원문과 적용 기준은 [전문 보고서 비교 기준](report-comparison.md)에 있어요.

## 11. 확장과 운영의 경계

역할 목록·가이드·출력 JSON Schema·도구 계약·화면 투영을 분리해요. 역할을 추가할 때는 이름만 등록하는 것으로 끝나지 않고 입력·출력·근거·검증·화면·이전 보고서 호환을 함께 정의해야 해요. 버전 있는 계약 덕분에 화면이나 모델 제공자가 바뀌어도 원본 판단을 읽을 수 있어야 해요.

모델 실행은 Codex CLI와 API 어댑터로 분리돼요. Codex 호출은 역할별 독립 실행이며 모델이 임의의 앱·셸·주문을 사용하는 경로는 차단해요. 계산과 저장은 일반 코드로 수행해요. 실제 분석과 합성 데모도 분리해요.

실패한 호출과 완료된 앞 단계는 남겨요. 제안 완료와 독립 평가 완료는 별도 상태이고 Q1이 실패해도 이미 저장한 제안을 지우거나 평가 성공으로 바꾸지 않아요. 일반 재시작이 모든 모델 호출을 중단 지점에서 자동 재개하는 기능은 아니에요.

기본 상시 서비스는 분석·제안용이에요. 별도 토스 주문 모듈이 존재하지만 모델의 결론이나 보고서 점수가 주문 권한으로 바뀌지 않아요. 이 문서의 정상 판단 순환에는 자동 주문을 포함하지 않아요.
