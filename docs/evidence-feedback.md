# 추가 근거 요청과 재판단

관점·검증·리더는 출력의 `evidence_requests`로 같은 실행의 자료 담당에게 추가 공시·관측·독해·분석 조건을 요청해요. 고정 decision question, 필요한 내용, access/extraction/analysis 구분, 기간·단위·출처 수용 조건, 판단 영향을 적어요.

최초 관점·검증·리더·최종 검증에서 나온 요청을 모아 최대 두 번, 한 번에 여섯 조사 대상까지 전달해요. 첫 묶음에서 넘친 요청은 두 번째 묶음으로 이어가요. 같은 역할·질문·필요 내용·수용 조건의 중복은 재실행하지 않으며 마지막 미처리 사유도 남겨요. frozen 또는 과거 기준일은 현재 자료를 취득하지 않아요.

자료 담당은 기존 `research_loop`에서 요청을 받고 허용된 회사·공시·관측·계산 도구로 응답해요. `evidence_responses`는 정확한 요청 ID, 실제 전달된 fact ID, 확보·미확보·분석 필요 상태, 이유와 남은 공백을 담아요. 공급자의 입력/출력, 도구 성공·실패 이벤트, 전달 사실의 해시가 응답에 연결돼요.

응답 이후 새 fact가 없어도 관점은 다시 판단해요. 기존 fact의 위치를 안내받았거나 자료를 얻지 못한 경우도 포함해요. 요청자는 자기 응답마다 `evidence_assessments`로 반영·여전히 미해결·관련 없음과 이유를 명시해요. 기록은 후속 입력/출력에 연결돼요. 공급 fact가 기간·의미·수용 조건을 경제적으로 충족하는지는 요청자와 최종 검증자가 판단하며 형식 검증만으로 증명하지 않아요.

관점 재판단 전에는 이번 실행의 이전 동료 비중·리더 대안 계산을 제거해요. 자기 요청·응답과 새로운 공통 근거를 읽고 다시 독립 판단하며, 이후 관점 비교·리더·최종 검증을 새로 수행해요. 원래 시황·관점과 각 출력은 보존해요. 후속 시황은 `evidence_followup` stage예요. 명시적으로 요청받은 사실은 일반 역할 투영에서 빠지는 상세 재무도 요청자에게 전달해요.

추가 근거 전체 368,000자 예산은 그대로예요. 종료된 자료 담당에게 새 몫을 지급하지 않아요. dispatch부터 return까지 공통 잔액과 실제 반환된 역할 잔액만 사용할 수 있어요. 기존에 다른 역할이 빌린 예산을 되찾지 않아요. 요청자 재판단에서는 자동 조사를 반복하지 않고 필요하면 다음 구조화 요청을 남겨요.

`evidence_feedback_request`, `evidence_feedback_dispatch`, `evidence_feedback_return`, `evidence_feedback_assessment` 이벤트와 보고서 `evidence_feedback`에서 왕복을 확인해요. 실제 자료·개인 맥락·원문은 기존 private DB에 저장돼요. 새 실행은 기존 보고서·실제 보유·개인 조건을 변경하거나 주문하지 않아요. 보류 해제·B1 개선·수익 성과는 이 구조 자체의 보장 사항이 아니에요.

## 요청 우선순위와 판단 정책

`decision_policy`의 calibration 정책을 지원하는 모델은 보류 원인을 `fact_verification`, `calculation_link`, `future_judgment`로 구분해요. 접근 실패·미추출·조사 배정 부족은 투자 부적합의 근거가 아니에요. 확인 가능한 사실·기간·단위·주식 기준·출처와 산식 검증은 유지하고, 미래 가정은 시나리오·비중·반증·재검토 조건으로 다뤄요. 현금·소규모 참여·더 높은 비중의 기회비용과 선택 이유도 같은 비교에 남겨요.

자료 요청은 선택 변경, 비중 변경, 시점 변경, 설명 보완 순으로 배정하고 사실·계산 무결성과 최종 검증의 요청을 함께 고려해요. 두 번, 회당 여섯 조사 대상 한도는 유지해요. 대상·주제·측정항목·기간·단위·기준이 모두 같은 요청만 조사를 공유하며, 요청자별 수용 조건과 응답·평가는 별도로 남겨요. 공유 대상의 응답은 회당 최대12개예요. 미래 가정은 반복 자료 수집으로 해결됐다고 표시하지 않아요. 부분 응답 뒤에는 새 근거 또는 원 요청에 연결한 구체적인 재조사 이유가 있어야 해요.

`incorporated`는 반영했다는 뜻이며 해결됐다는 뜻이 아니에요. 최종 선택에 영향을 주는 사실·계산 공백이 남으면 최종 정성 검증은 통과하지 못해요. 응답 또는 조사 배정을 받지 못한 요청도 원 요청·이유·시점·수용 조건·이연 사유와 최종 판단 연결을 보존해요.

## 회고와 지식의 실제 연결

다음 정상 실행은 이전 완료 보고서의 요청 원장을 `research_feedback_history`로 고정하고 reflection에 전달해요. 원 요청 ID를 인용해 반복 자료 공백·중복·우선순위/예산·수용 조건·계산/분석 실패를 구분하고 개선 제안의 적용 조건과 검증 방법을 남겨요. 실패 실행의 원 판단은 재사용하지 않으며, 안전한 과정 진단만 별도로 연결해요. frozen 재검토는 회고·지식 변경을 생략해요.

memory는 제안별 수용·통합·유보·거절을 평가하고, 수용된 변경만 원 reflection/요청 근거와 연결해 knowledge 버전으로 저장해요. 새 개선 가설은 검증 전 상태를 유지해요. 이후 조사 planner와 역할에 선택된 지식을 전달하고, `knowledge_feedback`과 사용 receipt에 고려·적용·미해결/비관련 및 영향을 남겨요. 전달되지 않은 지식을 사용했다고 주장할 수 없어요. 현재 관점은 동료의 새 의견을 읽지 않고 자기 요청·피드백을 읽으며, 리더·최종 검증은 종합 이견과 memory conflicts를 명시적으로 평가해요.

기한·적용 역할·조건을 보존하고 정확히 같은 지식만 정리해요. 같은 문장의 반복 횟수를 독립 근거나 확신 상승으로 바꾸지 않아요. 현재는 기억 검토 묶음 사이의 의미상 중복 후보를 전역 비교하는 단계와 현재 질문에 따른 지식 검색이 부족해요. 저장된 새 가설 일부가 입력 예산에서 제외될 수 있어요. 이 한계는 단순 예산 증액이나 조건을 무시한 자동 병합으로 해결하지 않아요.

실패 경계를 재사용한 실행은 `reused_prefix`로 표시하고 이미 적용한 지식을 다시 적용하지 않아요. 유효한 원 실패·재사용 receipt·완료 연결은 다음 정상 회고의 과정 진단에 한 번 전달해요. 같은 거부 응답을 원 실행과 재사용 실행에서 독립 사례로 중복 집계하지 않아요. 원 실패 자체는 계속 실패로 보존해요.

검증 수준은 기록 보존·전달, 모델이 보고한 지식 사용, 실제 내용의 판단 근거 충실성, 투자성과로 나눠요. 이벤트 연결과 테스트 통과는 앞 단계의 증거이며, 이후 효과는 실제 내용 비교나 별도 실험이 필요해요. 도구/역할 지침 수정 제안은 자동 코드 배포가 아니에요.

## 독립 검토와 원문 보존

완료 뒤 확인한 산술 오류와 판단 범위에 관한 의견은 `report_audit_finding`으로 덧붙일 수 있어요. 원 completed·모델 출력·판정·비중은 바꾸지 않아요. 내부 기록 함수는 같은 소유자의 수용된 원 출력·JSON 경로·원문 해시를 검증하고, 산술 정정에는 원 fact snapshot과 별도 검산 script/artifact 해시를 요구해요. 이 함수의 메타데이터 검사는 검산 스크립트 실행이나 내용 검토를 대신하지 않아요. 독립 검토자가 실제 산식·기간·단위와 산출물을 확인한 뒤 기록해야 해요.

API view와 화면은 ‘검산 정정’과 ‘판단 범위에 관한 검토 의견’을 구분해 원문·정정/의견·한계·검토 시점·출력 링크를 보여줘요. 검산 정정이 해당 질문의 원문과 일치하면 질문 옆에도 함께 표시해요. 원 보고서의 내용 해시 검증은 계속 유지해요.

다음 정상 history에는 해당 완료 보고서에 연결되고 새 실행 시작 전에 기록된 독립 검토를 제한된 과정 진단으로 전달해요. 원 실행을 failed로 바꾸거나 검토를 모델의 자기정정·새 시장 사실·독립 투자 근거·투자성과로 집계하지 않아요. 후속 해석이나 정정도 기존 기록을 수정하는 대신 별도 이벤트와 출처로 남겨야 해요.

이어가기 기록의 시각은 API view에서 요청 작성·등록·응답·평가별로 원 이벤트와 대조해요. 같은 소유자·실행·질문·원문·시점과 각 재사용 연결이 검증된 경우에만 최초 시각을 표시해요. 재사용 요청에 새 평가가 붙을 수 있으며, 검증되지 않은 연결을 새 기록이나 최초 기록으로 추정하지 않아요.
