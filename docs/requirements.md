## HTML 상황별 해석

S1: 납입 주기와 현 섹터 집중, 장기 목표를 함께 전달해요. 유지와 조정을 비교하고 예정 납입은 실제 성과로 계산하지 않아요.

S2: 소득·지출 차이, 사용 기간, 현금 필요, 손실 허용을 제약으로 삼아요. 현금 확보를 정량 검사하고 인플레이션·현금흐름 안정성·인출 순서 위험은 검증 에이전트가 평가해요.

S3: 이전 입력·시장·분석·제안·검증을 다시 불러와 회고해요. 당시 전제와 이후 결과를 비교하되 좋은 수익을 좋은 판단의 증거로 자동 간주하지 않아요.

## 검증 한계

통합 테스트와 합성 데모는 실행·저장·정리·권한·수치 계산의 동작을 확인해요. 실제 모델의 투자 분석 품질, 시장 데이터 공급자의 정확성, 세금·체결 비용 및 투자성과를 입증하지 않아요. 라이브 모델 호출은 설정된 제공자가 있어야 실행할 수 있어요. 특정 금융 데이터 공급자나 실제 계정은 이번 요청에서 정하지 않았어요.

공통 의미 지식의 정리는 운영자가 검토한 변경안으로 관리해요. 개인 memory agent는 주간 전체 검토를 수행하지만 모순 판별 자체는 확률적 모델 결과이므로 audit와 버전 복원으로 검토할 수 있게 해요. 모든 오래된 기록을 모델에 넣거나 과거 원본을 요약본으로 대체하지 않아요.
